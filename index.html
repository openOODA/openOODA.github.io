Design goals DESIGN.md north star

From the architectural blueprint: what openOODA is for. Goals below are the target shape of the language and ecosystem — progress is tracked separately.

Observe
Tight feedback
Sub-second compile loops, rich JSON metadata, dumps and outlines so humans and agents see the program fast.
Orient
Capability sandbox
Default-deny I/O; explicit tokens like &FsCap / &NetCap; scale toward quotas, taint, and attestation.
Decide
Contracts & proof
First-class requires / ensures, co-located verify, and automated contract fuzzing.
Act
Native multi-target
Bytecode for fast dev, LLVM for production native, WASM for edge/web, room for bare-metal and accelerators.

1. Language philosophy

  • OODA speed — observe → orient → decide → act as the product loop for humans and AI.
  • Mathematical contracts — requires / ensures as first-class bounds on behavior.
  • Data-oriented design — SoA layouts, zero-copy serialization goals.
  • AST macros & type-state — compile-time rewrite power; lifecycle-safe APIs.

2. AI-native tooling

  • Surgical patching — machine-readable diagnostics; AST-oriented agent fixes.
  • Token-minimized APIs — outline / reflect for cheap codebase views.
  • Intent-driven synthesis (goal) — contracts first; body synthesis/verification as north-star.
  • Global / overnight fuzzing (goal) — collaborative contract breaking beyond local runs.

3. Safety & security engine

  • Capability sandboxing — no ambient I/O; sealed tokens on the call graph.
  • Time / entropy / heap / CPU quotas (goal ladder) — purity and DoS bounds.
  • Taint & secret tracking (goal) — sensitive data never reaches unsafe sinks.
  • Contract fuzzer — ooda test --fuzz against requires/ensures.
  • 0ms GC via ARC / RAII — scope lifetimes without stop-the-world GC.
  • Advanced goals: temporal memory, call-graph integrity, metamorphic binaries (DESIGN.md §3).

4. Compiler & execution targets

  • Bytecode VM — fast development execution path (interpreter; design also discusses hot reload).
  • LLVM — production-oriented native IR / CPU performance.
  • WebAssembly — browsers and edge.
  • Further goals: GPU/NPU targets, bare-metal no_std, deterministic builds, compile-time FFI.

5. Ecosystem & DX

  • Self-hosted ecosystem — compiler first; package manager, LSP, registry as pure .oo goals.
  • Verifiable web of code (goal) — capability manifests and formal trust on imports.
  • Fearless concurrency (goal) — message passing; caps relinquished across threads.
  • std::core vs std::os — pure logic vs OS-capability surface.
  • Narrative diagnostics, HITL testing, universal LSP (DESIGN.md §5).

6. Tension points (by design)

  • Deterministic builds vs metamorphic binaries — disk hash vs RAM polymorphism.
  • Instant ARC free vs temporal/rollback memory — opt-in arenas for history.
  • Capability sandbox vs C/C++ FFI — explicit &UnsafeFFICap-class breach.
