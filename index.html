Tokens

Effects. In Rust, Go, Zig, and C, a function can use files or the network if the process can. In openOODA the function must hold an explicit token, for example &FsReadCap. You pass the token in; you cannot mint one from bytes. Missing or false tokens fail closed. See capabilities and how it works.

Writes. write_file needs &FsWriteCap and OODA_FS_WRITEDIR. If that environment value is not set, the write is denied. Absolute paths and symbolic links are refused. See getting started.

Secrets. Mark a struct field SECRET. Printing that field fails ooda check. process_exec is a secret sink. See language syntax.

Jail. On Linux, &SysCap applies a Landlock jail and POSIX setrlimit quotas. An empty path list fails closed. A zero quota fails closed. See capabilities and runtime limits.

Pins

Bytes. The SHA256 is the cryptographic identity of the file. A different file is a different package. ooda launch --exec re-checks the live bytes. A mismatch refuses. See binary pins and compiler limits.

Foreign ELF. A lock line does not grant Ooda tokens to a foreign ELF. Extra capabilities are refused. See how it works and commands.

Isolate. Measured isolate hashes the payload, the token, and the domain. That is a deterministic hash, not a hardware enclave. See capabilities, limits, and first run.

Locks

Lock. A lock line is name@version#sha256#CapName. The line binds the bytes to the permitted effect. Extra capabilities are refused. See capabilities and compiler verification.

Catalog. ooda add hello uses the stock store. ooda search walks every store you added. A package may list pay= on its manifest. See pay / 402 and commands.

Agents

Other languages expect a person to read full source files. openOODA gives a fast surgical loop: outline, reflect, fix, and patch one function. See language specs.

ooda lsp communicates with editors. check --json-errors outputs structured machine diagnostics. See how it works and all commands.

Files
  • ~/.local/bin/ooda — the command line
  • ~/.local/bin/oodac — the compiler
  • ~/.local/share/ooda/std/ — the library you import
  • ~/.local/share/ooda/runtime/ — C runtime for ooda run
  • ~/.local/share/ooda/share/fixtures/hello.oo — first program
  • ~/.config/ooda/env — PATH and OODA_*

ooda check typechecks. ooda run typechecks, emits C, calls host gcc, and runs the binary. ooda test runs verify next to the function. See commands and limits.

Defense

Moving Target Defense. Compiles morphologically diverse binaries on every build via AST control flow flattening, basic block permutation, and quadratic residue opaque predicates. Decompilation in Ghidra and IDA Pro is rendered intractable.

Exploit Mitigation. Scans intermediate emitted bytecode across instruction boundaries to eliminate unintended 0xC3 / 0xFF ROP/JOP gadgets and encrypts embedded strings with dynamic rolling keys and stack-transient decrypters.

Cyber Deception. Synthesizes capability-starved decoy entry points (admin_override, debug_backdoor) and canary credentials (sk_live_canary_*). Probing a decoy triggers instant fail-closed isolation and runtime threat alerts.

Autonomic Self-Healing. Embedded in-memory watchdog validates SHA256 page checksums of executable .text pages at startup, detecting inline hook injections and rolling back pristine gold-master bytes live in RAM without crashing. See runtime verification.

Zero-Trust Confinement. Strictly enforces Zero Ambient Authority. Morphed routines, dispatchers, and honeypots cannot mint tokens (&FsReadCap, &ProcessCap) or escape Landlock jails. Read active defense and capabilities.
