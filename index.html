Why openOODA

Effects. In Rust, Go, Zig, and C, a function can use files or the network if the process can. In openOODA, the function must hold a token. A token is a permission argument, for example &FsReadCap. If the token is not there, the call does not run. No token, no effect.

Agents. Other languages expect a person to read full source files. openOODA gives a short command loop: outline, reflect, fix, and patch one function. The agent does not send the full project to the model.

Secrets. If you print a key, the key leaves the program. openOODA marks secret fields with SECRET. Check stops a print of that field.

Packages. cargo add and go get fetch code with the full rights of the process. An openOODA lock line is name@version#sha256#CapName. The line names the hash and the permitted effect. Extra rights are refused. See the verifiable web of code.

The path. The usual path is: typecheck, emit C, run. You can also emit LLVM, wasm, or x86 when you ask. See the guide.

Safety

Tokens. A file, process, or network call takes a capability as an argument. A capability is a permission token. If the token is missing, false, or zero, the call stops. This is fail closed. Use the smallest token that does the job. Do not take &SysCap when &FsReadCap is enough.

Writes. write_file needs &FsWriteCap and OODA_FS_WRITEDIR. If that environment value is not set, the write is denied. Absolute paths and symbolic links are refused.

Secrets. Mark a field SECRET. println of that field fails check. A nearby field that is not secret is allowed. process_exec is a secret sink. A sink is a call that must not receive a secret.

Jail. On Linux, &SysCap can apply a Landlock jail and POSIX setrlimit. Landlock is a Linux kernel limit on which paths a process may use. setrlimit sets resource limits. An empty path list fails closed. A zero quota fails closed.

Security

Lock. A lock line is name@version#sha256#CapName. The line names the bytes and the permitted effect. Extra capabilities are refused. A path that leaves the package tree is refused.

Catalog. ooda add hello uses the stock store. ooda search walks every store you added. A yanked name is refused.

Launch. ooda launch --exec runs the gated payload after the hash, the caps, and the yank check.

Foreign binary. A foreign ELF file does not receive Ooda tokens from a lock line. The lock names a cap. It does not rewrite the binary.

Measured isolate. Measured isolate hashes the payload, the token, and the domain. You measure what you isolated. See the verifiable web of code.

Defense

Disk. The file on disk stays the same so a rebuild can match. See reproducible builds.

Memory layout. The defense in memory can change the layout at load. One exploit does not fit every machine. That is a metamorphic binary.

Call graph. Call-graph integrity seals the approved paths. A hijacked return cannot jump to a random gadget.

Zero-day. The stack is: contain with tokens, detect with contracts, raise cost with layout change. Read zero-day defense and disk versus memory.
