Tokens

Effects. In Rust, Go, Zig, and C, a function can use files or the network if the process can. In openOODA the function must hold a token, for example &FsReadCap. You pass the token in. You do not mint one from bytes. If the token is missing, false, or zero, the call stops. No token, no effect. See capabilities.

Writes. write_file needs &FsWriteCap and OODA_FS_WRITEDIR. If that environment value is not set, the write is denied. Absolute paths and symbolic links are refused.

Secrets. Mark a field SECRET. println of that field fails check. process_exec is a secret sink.

Jail. On Linux, &SysCap can apply a Landlock jail and POSIX setrlimit. An empty path list fails closed. A zero quota fails closed. The token list is on capabilities.

Pins

Bytes. The sha256 is the identity of the file. A different file is a different package. ooda launch --exec re-checks the live bytes. A mismatch refuses. See binary pins.

Foreign ELF. A lock line does not grant Ooda tokens to a foreign ELF. Extra capabilities are refused.

Isolate. Measured isolate hashes the payload, the token, and the domain. That is a hash, not a hardware enclave. The file on disk stays the same so a rebuild can match.

Locks

Lock. A lock line is name@version#sha256#CapName. The line binds the bytes to the permitted effect. Extra capabilities are refused. A path that leaves the package tree is refused.

Catalog. ooda add hello uses the stock store. ooda search walks every store you added. A yanked name is refused.

How packages work: packages. How pins work: binary pins. How tokens work: capabilities.

Agents

Other languages expect a person to read full source files. openOODA gives a short loop: outline, reflect, fix, and patch one function. The agent does not send the full project to the model.

ooda lsp talks to the editor. check --json-errors prints machine diagnostics. The full command list is on commands.

Files
  • ~/.local/bin/ooda — the command line
  • ~/.local/bin/oodac — the compiler
  • ~/.local/share/ooda/std/ — the library you import
  • ~/.local/share/ooda/runtime/ — C runtime for ooda run
  • ~/.local/share/ooda/share/fixtures/hello.oo — first program
  • ~/.config/ooda/env — PATH and OODA_*

ooda check typechecks. ooda run typechecks, emits C, calls host gcc, and runs the binary. ooda test runs verify next to the function. ooda run does not.
