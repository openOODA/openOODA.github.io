Tokens

Non-Ambient Authority. In C, Rust, Go, and Zig, any routine can access files or networks if the process can. openOODA enforces Zero Ambient Authority: an effect requires an explicit, unforgeable token (e.g. &FsReadCap, &NetCap). No token, no effect. See capabilities and how it works.

HMAC Attenuation & Writes. Capabilities cannot be minted from arbitrary bytes. write_file requires &FsWriteCap bounded by OODA_FS_WRITEDIR. Token derivation uses cryptographic HMAC seals to narrow authority down call trees. See getting started.

Information Flow & Secrets. Struct fields marked SECRET are statically barred from unauthenticated sinks. Accidental logging or printing fails ooda check at compile time. See language grammar.

Kernel Sandboxing. Holding &SysCap enforces Linux Landlock jails and POSIX setrlimit quotas. Undefined boundaries fail closed. See capabilities and runtime limits.

Pins

Cryptographic Identity. A package's identity is mathematical: $ID = \text{SHA256}(Bytes)$. A different byte sequence is an entirely distinct package. ooda launch --exec verifies live binaries before transfer. See binary pins and compiler limits.

Foreign ELF Confinement. Foreign ELF binaries cannot inherit or synthesize openOODA tokens. Undeclared capabilities are refused at the entry gate. See how it works and commands.

Measured Domain Isolation. Isolates compute deterministic hashes over payload, token, and domain boundaries, guaranteeing verifiable hermetic execution. See capabilities, limits, and first run.

Locks

Capability-Bound Contracts. Every lock line binds name@version#sha256#CapName. Dependencies can never access undeclared system resources or exfiltrate state. See capabilities and compiler verification.

Store Ecosystem & 402 Monetization. ooda add hello resolves packages from decentralized registries. Packages declare value exchange natively via HTTP 402 / x402 protocol quotes. See pay / 402 and commands.

Systemic dependencies: packages. Cryptographic integrity: binary pins. Living defenses: active defense.

Agents

Surgical 90% Context Reduction. Traditional languages force AI agents to parse sprawling codebases, causing context window exhaustion. openOODA provides a direct surgical loop: outline, reflect, fix, and patch one isolated AST function. See language specs.

Machine-Deterministic Diagnostics. ooda lsp provides real-time completion while check --json-errors feeds structured, deterministic compiler diagnostics back to autonomous agents. See how it works and all commands.

. ~/.config/ooda/env

Zero Hidden State. Pure XDG directory hierarchy eliminates configuration drift. ooda check typechecks, ooda run emits clean C for host gcc, and ooda test validates inline verify contracts. See commands and limits.

Defense

Moving Target Defense. Inverts the economics of cyber warfare by turning static binaries into mutating organisms. Compiles polymorphic binaries on every build via AST control flow flattening, basic block permutation, and quadratic residue opaque predicates, rendering Ghidra/IDA Pro analysis intractable.

Exploit Mitigation. Scans intermediate bytecode across instruction boundaries to destroy unintended 0xC3 / 0xFF ROP/JOP gadgets and encrypts embedded strings with dynamic rolling keys and stack-transient decrypters.

Cyber Deception. Plants capability-starved decoy symbols (admin_override, debug_backdoor) and canary credentials (sk_live_canary_*). Probing a decoy triggers instant fail-closed isolation and threat alerts.

Autonomic Self-Healing. Embedded in-memory watchdog registers SHA256 checksums of .text pages at startup, detecting inline debugger/hook injections and rolling back pristine gold-master bytes live in RAM without crashing. See runtime verification.

Zero-Trust Confinement. Strictly enforces Zero Ambient Authority. Morphed dispatchers and honeypots cannot synthesize tokens (&FsReadCap, &ProcessCap) or escape Landlock jails. Read active defense and capabilities.
