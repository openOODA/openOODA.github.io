Design goals DESIGN.md

North star architecture — what openOODA is for. Goals are not claims of full implementation.

Observe
Tight feedback
Fast compile loops, rich metadata, dumps and outlines for humans and agents.
Orient
Capability sandbox
Default-deny I/O; explicit &FsCap / &NetCap and richer quota/taint goals.
Decide
Contracts & proof
First-class requires / ensures, co-located verify, contract fuzzing.
Act
Native multi-target
Bytecode for dev, LLVM for native, WASM for edge — plus bare-metal / accelerator goals.

1. Language philosophy

  • OODA speed — tight observe → orient → decide → act loops.
  • Mathematical contracts — requires / ensures as first-class bounds.
  • DOD / SoA, AST macros, type-state machines (goals).

2. AI-native tooling

  • outline / reflect / patch — token-cheap agent surface.
  • JSON diagnostics — machine-readable errors.
  • Intent synthesis, global overnight fuzzing (goals).

3. Safety & security

  • Capability sandbox — no ambient I/O.
  • Contract fuzzer — break requires/ensures.
  • ARC / RAII — 0ms GC direction; advanced integrity goals in DESIGN.

4. Targets & ecosystem

  • Bytecode VM, LLVM, WASM; GPU/NPU and bare-metal as goals.
  • Self-hosted ecosystem (LSP, registry, package manager) as goals.
  • std::core vs std::os capability split.
